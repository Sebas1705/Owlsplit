# P11c · iOS — Implementation Plan

> **For agentic workers:** Use `mobiai-mobile-executing-plans-with-subagents` (recommended) or `mobiai-mobile-executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Make the iOS app exist as a project that compiles and links completely (not just the Kotlin framework), with what Android already has: Firebase, sharing, QR scanning, Google, invite links and "reduce motion".

**Architecture:**
- `iosApp/project.yml` (XcodeGen): app `es.sebas1705.owlsplit`, iOS 16+, Firebase iOS SDK 11.8.0 via SPM (the GitLive 2.7.0 version: Core, Auth, Firestore, Crashlytics) and Google Sign-In 8; a phase that builds the `ComposeApp` framework (`embedAndSignAppleFrameworkForXcode`); generated `Info.plist` (camera, languages, Google scheme); `iosApp.entitlements` with `applinks:owlsplit.web.app`. The `.xcodeproj` is not versioned.
- Swift: `iOSApp` configures Firebase if there is a `GoogleService-Info.plist`, passes links (`onOpenURL`, `NSUserActivityTypeBrowsingWeb`) to `handleIncomingLink` and the Google callback to `GIDSignIn`; `GoogleSignInSwift` implements `GoogleSignInBridge`.
- Kotlin (`composeApp/iosMain`): `IosTextSharer` (`UIActivityViewController`), `IosQrScanner` (full-screen AVFoundation), `IosGoogleCredentials` (on top of the Swift bridge), `systemReduceMotion()` (`UIAccessibilityIsReduceMotionEnabled`), `handleIncomingLink`.
- Common: the Google token also carries `accessToken` (Firebase requires it on iOS); `LocalReduceMotion` in `core:ui`.
- CI: the iOS job generates the project and builds the app for the simulator, unsigned.

**Platform:** iOS (built on macOS CI; no device or Mac on SEBAS-PC)

**Depends on:** P11b.

---

## Decisions

1. **XcodeGen** instead of a hand-made `.xcodeproj`: without a Mac you can't create or review an Xcode project; a YAML file you can, and CI generates and builds it on every PR.
2. **Google in Swift**: the Google Sign-In SDK is Swift; Kotlin defines `GoogleSignInBridge` and Swift implements it. The Google URL scheme (`GOOGLE_REVERSED_CLIENT_ID`) is a placeholder until Google is enabled in Firebase; meanwhile the app hides Google on iOS.
3. **Custom scanner** with AVFoundation (VisionKit `DataScannerViewController` isn't accessible from Kotlin); full screen so it can't be swiped away without returning a result.
4. **Universal Links**: the code and the entitlement are in place; `apple-app-site-association` on Hosting is missing, and it needs the Team ID.

## Pending on the owner (Apple Developer account)

- **Team ID**: signing, `apple-app-site-association` (`TEAMID.es.sebas1705.owlsplit`, paths `/j/*`) and TestFlight.
- **Sign in with Apple**: mandatory on the App Store if Google is offered (guideline 4.8). Needs the capability on the App ID and the Apple provider in Firebase Authentication (Services ID and key). It is then implemented following the Google pattern (`OAuthProvider` `apple.com` credential with a nonce).
- **Test on an iPhone** (TestFlight) criteria 1 and 5 of [ACCEPTANCE.md](../ACCEPTANCE.md).
- Background uploads (BGTaskScheduler): an improvement, not a blocker; sync already works with the app open.
