# P15 · Avisos de actualización

**Goal:** que actualizar la app sea pulsar un botón. Fuera de la Play Store nadie avisa de que hay una versión nueva; ahora lo hace la propia app.

## Estudio

| Opción | Cómo | Por qué sí / no |
|---|---|---|
| **A. `latest.json` de la web (elegida)** | La app lee `https://owlsplit.web.app/download/latest.json`, que ya escribe deploy-firebase.yml tras cada release, y compara su `versionCode`. | Sin servidor ni claves; el fichero ya existe y se sirve con `no-cache`. Un solo GET al abrir Inicio. |
| B. API de GitHub Releases | `GET /repos/…/releases/latest` | Límite de 60 peticiones/hora por IP, ignora las pre-releases en `latest` y obliga a interpretar etiquetas. |
| C. Firebase Remote Config | Un parámetro `latest_version_code` | Otra dependencia y otro paso manual en cada release. |
| D. Play In-App Updates | API de Google Play | Solo para instalaciones desde la Play Store (aparcada). |
| E. App Distribution | El SDK de App Tester avisa de builds nuevas | Solo para testers, y pide iniciar sesión de tester. |

**Identificador:** el `versionCode`. Es el número de commits del commit compilado (`git rev-list --count`), así que crece siempre y builds de `main` y tags comparten secuencia. Comparar `versionName` (`1.0.0-beta.5`) obligaría a ordenar semver con sufijos; el código es un entero y es lo que Android usa para decidir si un APK instala encima.

## Diseño

- **Web:** `latest.json` gana `versionCode` = `git rev-list --count <tag>` (checkout con historial completo). Ficheros antiguos sin el campo se ignoran.
- **App:**
  - `updatableVersionCode` (expect/actual): el `BuildConfig.VERSION_CODE` en builds release de Android; null en debug e iOS, que nunca preguntan.
  - `ReleaseFeed` / `HostingReleaseFeed` (Ktor) lee el JSON; cualquier fallo es «nada que ofrecer».
  - `CheckForUpdate` devuelve la release si su código es mayor que el instalado. Las builds de `main` (App Distribution) van por delante del último tag, así que no se les pide volver atrás.
  - Inicio muestra «Nueva versión: X» con «Actualizar» (abre la URL del APK en el navegador, que lo descarga; al abrirlo, Android lo instala encima porque está firmado con la misma clave) y «Ahora no» (guarda ese `versionCode` en `UpdateSettings`; la siguiente versión vuelve a avisar).
- **Sin cambios de permisos:** no se pide `REQUEST_INSTALL_PACKAGES`; descarga e instalación las hace el sistema.
