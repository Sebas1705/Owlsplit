# P15 · Update notices

**Goal:** make updating the app a single button press. Outside the Play Store nobody tells you there is a new version; now the app itself does.

## Study

| Option | How | Why yes / no |
|---|---|---|
| **A. Website `latest.json` (chosen)** | The app reads `https://owlsplit.web.app/download/latest.json`, which deploy-firebase.yml already writes after each release, and compares its `versionCode`. | No server or keys; the file already exists and is served with `no-cache`. A single GET when Home opens. |
| B. GitHub Releases API | `GET /repos/…/releases/latest` | 60 requests/hour per IP limit, ignores pre-releases in `latest` and forces parsing tags. |
| C. Firebase Remote Config | A `latest_version_code` parameter | Another dependency and another manual step on every release. |
| D. Play In-App Updates | Google Play API | Only for installs from the Play Store (parked). |
| E. App Distribution | The App Tester SDK announces new builds | Testers only, and requires a tester sign-in. |

**Identifier:** the `versionCode`. It is the commit count of the built commit (`git rev-list --count`), so it always grows and `main` and tag builds share a sequence. Comparing `versionName` (`1.0.0-beta.5`) would require sorting semver with suffixes; the code is an integer and it is what Android uses to decide whether an APK installs over the existing one.

## Design

- **Web:** `latest.json` gains `versionCode` = `git rev-list --count <tag>` (checkout with full history). Older files without the field are ignored.
- **App:**
  - `updatableVersionCode` (expect/actual): `BuildConfig.VERSION_CODE` in Android release builds; null in debug and iOS, which never ask.
  - `ReleaseFeed` / `HostingReleaseFeed` (Ktor) reads the JSON; any failure means "nothing to offer".
  - `CheckForUpdate` returns the release if its code is higher than the installed one. `main` builds (App Distribution) are ahead of the latest tag, so they aren't asked to go back.
  - Home shows «Nueva versión: X» ("New version: X") with «Actualizar» ("Update": opens the APK URL in the browser, which downloads it; when opened, Android installs it over the existing app because it is signed with the same key) and «Ahora no» ("Not now": saves that `versionCode` in `UpdateSettings`; the next version notifies again).
- **No permission changes:** `REQUEST_INSTALL_PACKAGES` is not requested; the system handles download and installation.
