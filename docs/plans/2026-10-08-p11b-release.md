# P11b · Entrega: Crashlytics, un proyecto Firebase, firma y distribución — Implementation Plan

> **For agentic workers:** Use `mobiai-mobile-executing-plans-with-subagents` (recommended) or `mobiai-mobile-executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Dejar la app lista para repartirse: errores inesperados en Crashlytics con un mensaje genérico ([9](../designs/2026-10-07-owlsplit-core-design.md#9-gestión-de-errores)), builds firmadas y distribución a testers por Firebase App Distribution ([11](../designs/2026-10-07-owlsplit-core-design.md#11-cicd)).

**Architecture:**
- `core:common`: `UnexpectedErrors` + `ErrorReporter`; `MVIBaseViewModel.execute` envía ahí lo que escapa (la pantalla sigue viva).
- `composeApp`: `AppConfig` como objeto normal e `isDebugBuild` (expect/actual: `BuildConfig.DEBUG`, `Platform.isDebugBinary`); `CrashReporting` (log + Crashlytics no fatal con GitLive); mensaje genérico en la raíz; `DebugBadge`; plugin de Crashlytics junto al de Google Services; colección solo en release (manifiesto); `applicationIdSuffix = ".debug"` en debug; versión y firma desde variables de entorno.
- Firebase: un solo proyecto `owlsplit` con Firestore `eur3`, dos apps Android (release y `.debug`), una iOS, reglas, índices y Hosting (`owlsplit.web.app`).
- CI: acción `build-release`, `distribute.yml` (`main` → App Distribution), `release.yml` (tag → GitHub Release + App Distribution) y `deploy-firebase.yml` (`main` → reglas, índices y Hosting).
- Scripts: `setup-firebase-env.sh`, `setup-release-keystore.sh`, `setup-ci-access.mjs`, `doppler-sync-local.sh`.

**Platform:** KMP (Android: build de release con R8 comprobada; iOS compila en CI)

**Depende de:** P11a.

## Decisiones

1. **Un solo proyecto Firebase** (`owlsplit`), decidido por el propietario el 2026-10-08: hasta que haya usuarios reales, desarrollo/staging/producción separados triplican la configuración (Auth, Doppler, huellas, despliegues) sin aportar. Se crearon `owlsplit-stg` y `owlsplit` y después se borraron `owlsplit-stg` y `owlsplit-dev` (solo datos de prueba). El ID de un proyecto no se puede renombrar, por eso se conserva el nuevo `owlsplit` (enlaces `owlsplit.web.app`).
2. **Dos apps Android en el mismo proyecto**: `es.sebas1705.owlsplit` (release: testers y usuarios) y `es.sebas1705.owlsplit.debug` (desarrollo local, clave de depuración, sin Crashlytics). Se instalan una junto a otra; comparten base de datos.
3. **Crashlytics**: activo en release desde el arranque (metadato del manifiesto), apagado en debug. Lo no fatal: lo que escapa de `execute {}` en un ViewModel, con el mensaje "Algo ha fallado" y nunca la traza.
4. **R8**: la build de release (minificada) se probó en el emulador: arranque, sincronización, invitación, historial, saldos y tipo de cambio de Frankfurter; sin reglas extra.
5. **Distribución por Firebase App Distribution** al grupo `testers`: cada merge a `main` (`main-<n>`) y cada tag `vX.Y.Z` (además, GitHub Release con APK y AAB). Misma app y clave; `versionCode` = número de commits, que siempre crece.
6. **Secretos**: todo en Doppler `owlsplit/prd`, escrito por los scripts con la autorización del propietario; contraseñas aleatorias que nunca se imprimen; la clave de CI va directa a Doppler; GitHub solo tiene `DOPPLER_TOKEN` (solo lectura).
7. **Despliegue desde `main`** con la cuenta de servicio `owlsplit-ci` (permisos mínimos).
