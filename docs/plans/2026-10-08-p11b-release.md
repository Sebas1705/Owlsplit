# P11b · Entrega: Crashlytics, staging y producción, firma y publicación — Implementation Plan

> **For agentic workers:** Use `mobiai-mobile-executing-plans-with-subagents` (recommended) or `mobiai-mobile-executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Dejar la app lista para repartirse: errores inesperados en Crashlytics con un mensaje genérico ([9](../designs/2026-10-07-owlsplit-core-design.md#9-gestión-de-errores)), un proyecto Firebase por entorno, builds de producción firmadas y el flujo de publicación por tag ([11](../designs/2026-10-07-owlsplit-core-design.md#11-cicd)).

**Architecture:**
- `core:common`: `UnexpectedErrors` + `ErrorReporter`; `MVIBaseViewModel.execute` envía ahí lo que escapa (la pantalla sigue viva).
- `composeApp`: perfiles como `EnvProfile` (sufijo, FX, Hosting, `crashReporting`); `CrashReporting` (log + Crashlytics no fatal con GitLive); mensaje genérico en la raíz; plugin de Crashlytics junto al de Google Services; colección por entorno en el manifiesto; versión y firma desde variables de entorno.
- Firebase: `owlsplit-stg` y `owlsplit` con Firestore `eur3`, apps, reglas, índices y Hosting; `.firebaserc` con `dev`, `stg`, `prd`.
- CI: acción `build-release`, `release.yml` (tag → GitHub Release + App Distribution) y `deploy-firebase.yml` (`main` → producción).
- Scripts para el propietario: `setup-firebase-env.sh`, `setup-release-keystore.sh`, `setup-ci-access.mjs`.

**Platform:** KMP (Android: build de producción con R8 comprobada; iOS compila en CI)

**Depende de:** P11a.

---

## Decisiones

1. **Producción se llama `owlsplit`**: su Hosting es `owlsplit.web.app`, el host de los enlaces de invitación de producción. Staging tiene su propio sitio (`owlsplit-stg.web.app`).
2. **Crashlytics**: activo en staging y producción desde el arranque (metadato del manifiesto), apagado en desarrollo; los mapeos de R8 solo se suben donde hay informes. Lo no fatal: lo que escapa de `execute {}` en un ViewModel, con el mensaje "Algo ha fallado" y nunca la traza.
3. **R8**: la build de release (minificada) se probó en el emulador: arranque, sincronización, invitación, historial, saldos y tipo de cambio de Frankfurter; sin reglas extra.
4. **Secretos**: el agente no escribe en Doppler ni en los secretos de GitHub (lo bloquea la política de permisos): lo hacen tres scripts que ejecuta el propietario. Contraseñas generadas al azar que nunca se imprimen; la clave de CI va directa a Doppler.
5. **Despliegue de producción desde `main`** con una cuenta de servicio de permisos mínimos; staging y dev a mano.
6. **Versiones**: `versionName` del tag, `versionCode` = número de ejecución del flujo (como YouKnow).
