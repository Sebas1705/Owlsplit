# P11b · Delivery: Crashlytics, a single Firebase project, signing and distribution — Implementation Plan

> **For agentic workers:** Use `mobiai-mobile-executing-plans-with-subagents` (recommended) or `mobiai-mobile-executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Get the app ready to hand out: unexpected errors in Crashlytics with a generic message ([9](../designs/2026-10-07-owlsplit-core-design.md#9-error-handling)), signed builds and distribution to testers through Firebase App Distribution ([11](../designs/2026-10-07-owlsplit-core-design.md#11-cicd)).

**Architecture:**
- `core:common`: `UnexpectedErrors` + `ErrorReporter`; `MVIBaseViewModel.execute` sends whatever escapes there (the screen stays alive).
- `composeApp`: `AppConfig` as a plain object and `isDebugBuild` (expect/actual: `BuildConfig.DEBUG`, `Platform.isDebugBinary`); `CrashReporting` (log + non-fatal Crashlytics with GitLive); generic message at the root; `DebugBadge`; Crashlytics plugin next to the Google Services one; collection only in release (manifest); `applicationIdSuffix = ".debug"` in debug; version and signing from environment variables.
- Firebase: a single `owlsplit` project with Firestore `eur3`, two Android apps (release and `.debug`), one iOS app, rules, indexes and Hosting (`owlsplit.web.app`).
- CI: `build-release` action, `distribute.yml` (`main` → App Distribution), `release.yml` (tag → GitHub Release + App Distribution) and `deploy-firebase.yml` (`main` → rules, indexes and Hosting).
- Scripts: `setup-firebase-env.sh`, `setup-release-keystore.sh`, `setup-ci-access.mjs`, `doppler-sync-local.sh`.

**Platform:** KMP (Android: release build with R8 verified; iOS compiles in CI)

**Depends on:** P11a.

## Decisions

1. **A single Firebase project** (`owlsplit`), decided by the owner on 2026-10-08: until there are real users, separate development/staging/production triple the configuration (Auth, Doppler, fingerprints, deployments) without adding value. `owlsplit-stg` and `owlsplit` were created, and then `owlsplit-stg` and `owlsplit-dev` were deleted (test data only). A project ID can't be renamed, which is why the new `owlsplit` is kept (`owlsplit.web.app` links).
2. **Two Android apps in the same project**: `es.sebas1705.owlsplit` (release: testers and users) and `es.sebas1705.owlsplit.debug` (local development, debug key, no Crashlytics). They install side by side; they share the database.
3. **Crashlytics**: on in release from startup (manifest metadata), off in debug. Non-fatal: whatever escapes `execute {}` in a ViewModel, with the message "Algo ha fallado" ("Something went wrong") and never the stack trace.
4. **R8**: the (minified) release build was tested on the emulator: startup, sync, invite, history, balances and Frankfurter exchange rate; no extra rules.
5. **Distribution through Firebase App Distribution** to the `testers` group: every merge to `main` (`main-<n>`) and every `vX.Y.Z` tag (plus a GitHub Release with APK and AAB). Same app and key; `versionCode` = commit count, which always grows.
6. **Secrets**: everything in Doppler `owlsplit/prd`, written by the scripts with the owner's authorization; random passwords that are never printed; the CI key goes straight to Doppler; GitHub only has `DOPPLER_TOKEN` (read-only).
7. **Deployment from `main`** with the `owlsplit-ci` service account (minimal permissions).
