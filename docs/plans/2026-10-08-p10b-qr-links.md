# P10b · Invites: QR, Hosting page and App Links — Implementation Plan

> **For agentic workers:** Use `mobiai-mobile-executing-plans-with-subagents` (recommended) or `mobiai-mobile-executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Complete invites ([3.8](../designs/2026-10-07-owlsplit-core-design.md#38-invitations)): the invite link opens the app (App Links) or, if it isn't installed, a page with the code; the Invite screen shows a QR code with the link and Join can scan it.

**Architecture:**
- `core:ui`: `QrCode` (qrose 1.1.2, always dark on white) and the `QrScanner` port.
- `composeApp`: `AndroidQrScanner` (Play services Google code scanner: its own camera, no camera permission for the app); `https://<invite host>/j/` filter with `autoVerify` (host per environment via `manifestPlaceholders`), `singleTask` `MainActivity` that hands the link to `IncomingInvites`; `AppRoot` opens Join with the code once the tabs are visible (after onboarding the first time).
- `firebase/hosting`: `join.html` for `/j/**` (code, "Abrir en Owlsplit" ("Open in Owlsplit") with `intent://` on Android, copy code, steps if there is no app), home page and `.well-known/assetlinks.json` (`.dev` package with the debug SHA‑256 fingerprint).

**Platform:** KMP (Android verified on emulator against `owlsplit-dev`; iOS compiles in CI)

**Depends on:** P10a.

---

## Decisions

1. **QR**: qrose 1.1.2, the latest version that doesn't require Compose 1.12 or compileSdk 37 (Dependabot holds it back). It contains the link, not just the code: a phone without the app opens the Hosting page with the system camera.
2. **Scanner**: Google code scanner (`play-services-code-scanner`); the module is downloaded the first time the scanner is resolved. A QR code that isn't from Owlsplit gives "código no válido" ("invalid code"). On iOS there is no scan option until P11 (AVFoundation).
3. **App Links**: verified with `assetlinks.json`; the link opens Join with the code already looked up. If the app has no profile, the link waits until onboarding finishes. Universal Links (iOS) in P11 with the Xcode project (`apple-app-site-association` needs the Team ID).
4. **`/j/<code>` page**: static, no Firebase SDK; validates the code alphabet; on Android it offers `intent://…;package=<environment package>` to open the app even if the browser doesn't hand over the link. No store links until the app is published.
5. **Production**: the `owlsplit.web.app` site and the release key fingerprint come with P11 (prd project and signing).
